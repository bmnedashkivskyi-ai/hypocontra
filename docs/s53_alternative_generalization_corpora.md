# §5.3: пошук альтернативних/додаткових корпусів для крос-доменної генералізації (research, 2026-09-13)

Дослідницьке питання: чи існує новіша або структурно ближча до таксономії
HypoContra (§3: type1-4, зокрема `Apparent`/type4 — контекстуальна, не
логічна суперечність) заміна чи доповнення до Alamri & Stevenson (2016) як
джерела fine-tune-даних для §5.3 (crossdomain zero-shot). Приводом слугував
citation-check пункт §11.2 статті: джерелу рівно 10 років, межа правила
"flag sources older than 10 years"; рішення того прогону — залишити
цитування як є (робота лишається seminal для методології §4), але
позначено "за бажання — знайти новіший супровідний огляд/розширення цього
корпусу для балансу свіжості джерел".

**Важливо:** це доповнення, не заміна. Alamri & Stevenson лишається
обґрунтованим джерелом методології §4 (найближчий існуючий аналог
розмітки пар гіпотез) незалежно від результату цього пошуку.

## Оцінка придатності для §5.3-подібного протоколу

Поточний скрипт `src/baseline_generalization_alamri_stevenson.py` очікує
бінарну (YS/NO) джерельну схему й будує з неї комбінаторні
Contradiction/NotContradiction-пари для fine-tune, потім оцінює zero-shot
на HypoContra n=59. Ключове обмеження цього підходу (задокументоване в
`docs/generalization_report.md`) — джерело структурно не має еквівалента
`Apparent`, тому `Apparent`-recall завжди буде 0 незалежно від якості
моделі.

- **NLI4CT** успадковує те саме обмеження (бінарна схема), але дає
  **другу незалежну, свіжішу, більшу** crossdomain-точку даних тим самим
  скриптовим підходом (мінімальна адаптація — інший парсер вхідного
  формату). Це підсилює §5.3 (одна крос-доменна перевірка → дві
  незалежні, узгодженість чи розбіжність результату сама по собі
  інформативна), не вирішуючи Apparent-прогалину.
- **RevCI**, якщо дані виявляться публічними й читабельними — єдиний
  кандидат, що структурно міг би дати приклади, близькі до type4/Apparent
  (градуйована інтенсивність замість бінарної), але він **NLP-домен, не
  біомедичний** — його використання означало б додати *same-domain*
  generalization check (інша вісь, ніж §5.3's crossdomain-задум), а не
  замінник Alamri&Stevenson.
- **HealthContradict** і **BioDivergence** вимагають істотнішої адаптації
  пайплайна (QA-структура; непідтверджена доступність відповідно) —
  нижчий пріоритет без додаткової перевірки.

## RevCI: детальна розвідка (2026-09-13) — чому не реалізовано як третю fine-tune-точку

Дані реально завантажено й перевірено (`github.com/sandeep82945/Contradiction-Intensity`,
CC BY 4.0, `Data/Human_Annotated_Data.json` — 75 пар статей, 197
aspect-рівневих інстансів контрадикції; `Data/Data_Generated_Using_IMPACT.json`
— 1000 пар, 2640 інстансів, але LLM/IMPACT-автогенеровані, без людської
верифікації). Структура кожного інстансу:

```json
{"contradiction": "...", "aspect": "clarity", "evidence": ["речення з Review 1", "речення з Review 2"], "intensity": {"score": 1-3, "justification": "..."}}
```

`evidence` — рівно два природномовні речення (по одному з кожного
рецензування) — структурно НАБАГАТО ближче до Alamri&Stevenson-подібних
claim-vs-claim пар, ніж NLI4CT-подібний claim-vs-evidence-paragraph
формат. Градуйована `intensity` (1=implicit/слабка, 2=explicit mild,
3=direct strong) теоретично приваблива як перший знайдений кандидат на
`Apparent`-подібний сигнал (score 1 ≈ type4 контекстуальна/неявна
суперечність, score 3 ≈ type1 пряма логічна).

**Чому не реалізовано як fine-tune-протокол, аналогічний Alamri&Stevenson/NLI4CT:**

1. **Немає негативного класу.** Обидва релізовані файли містять ЛИШЕ
   підтверджені контрадикції (в IMPACT-файлі усі 1000/1000 записів мають
   ≥1 знайдену контрадикцію) — датасет побудований як
   "знайти й охарактеризувати контрадикції", не як збалансований
   класифікаційний бенчмарк. Стаття згадує "800 review pairs: 352 з
   контрадикцією / 448 без" — ця статистика не відповідає жодному з
   реально випущених файлів (можливо, внутрішня стадія скринінгу, не
   експонована як окремий датасет). Побудова `NotContradiction`-пар
   вимагала б власної стратегії негативного семплінгу (наприклад, пари
   речень з різних aspect-категорій чи з непов'язаних review-пар) — це
   самостійне методологічне рішення поза оригінальною розміткою
   датасету, з ризиком тривіально легких негативів, що спотворять
   результат generalization-перевірки.
2. **Малий обсяг людської розмітки.** n=197 (human-annotated,
   aspect-рівень) — приблизно у 9 разів менше за NLI4CT (n=1700), який
   УЖЕ показав нестабільну/близьку до колапсу поведінку при fine-tune
   (`docs/generalization_report_nli4ct.md`). Менший датасет — вищий
   ризик ще нестабільнішого результату, важче інтерпретованого.
   Автогенерований IMPACT-файл (n=2640) більший, але несе ту саму
   циркулярність, що вже задокументована для LLM few-shot baseline
   (`results/baseline_llm_fewshot_metrics_NOTE.md`) — LLM-розмічені дані
   як "ground truth" для навчання іншої моделі.

**Висновок:** RevCI НЕ рекомендується як третя fine-tune/zero-shot точка
для §5.3 тим самим протоколом. Якщо project захоче використати RevCI
далі — реалістичніший шлях: якісне порівняння таксономій (6
aspect-категорій + 3-рівнева graded intensity RevCI проти type1-4 §3
HypoContra) як текстовий аргумент у §2/§8 статті (споріднена робота,
що незалежно приходить до потреби градуйованої, не бінарної шкали
контрадикції — підсилює методологічний вибір HypoContra), а не як
код/експеримент. Не додано в поточну реалізацію.
